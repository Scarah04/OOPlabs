LIBRARY MANAGEMENT SYSTEM - CLASS DIAGRAM AND REPORT
=====================================================

1. OBJECTIVE
Build a small but complete application that combines classes, encapsulation,
inheritance, abstraction, polymorphism, interfaces, custom exceptions, collections,
streams and file I/O (Labs 1 to 10).

2. CLASS DIAGRAM (text form)

   Exception <- ItemNotAvailableException

   Main : text menu that uses Library.

3. HOW EACH REQUIREMENT IS MET
- Book, Member, Loan with private fields, validation and toString:
  fields are private; constructors reject empty ids/titles/names; toString() overridden.
- Abstract LibraryItem with Book and Dvd, each with loanPeriodDays():
  Book = 21 days, Dvd = 7 days (inheritance, abstraction, polymorphism).
- Borrowable interface with borrow(Member) and giveBack(): implemented by LibraryItem.
- Custom exceptions: ItemNotAvailableException (item already on loan) and
  MemberLimitExceededException (more than 3 loans).
- Maps keyed by id: Library keeps Map<String, LibraryItem> and Map<String, Member>.
- CSV persistence: save() writes items.csv, members.csv, loans.csv on exit;
  load() reads them at start (folder library_data).
- Menu: add item, register member, borrow, return, list overdue, search by title (streams).

4. MARKING GUIDE MAPPING
- Correct class design (25): encapsulation, inheritance, interface, abstraction used.
- Polymorphism (10): loanPeriodDays() and getType() resolved at run time; Loan computes due date.
- Exceptions (15): two custom checked exceptions; IllegalArgumentException for unknown ids.
- Collections and streams (15): HashMap, List, stream().filter().sorted().toList().
- File persistence (15): data survives between runs (shown in RESULTS.txt).
- Code quality (10): meaningful names, comments, no duplicated logic.
- Report and class diagram (10): this document.

6. CONCLUSION
The project shows how the four OOP pillars work together. Encapsulation protects state,
inheritance and abstraction remove duplication, polymorphism lets Library treat every
item the same way, and exceptions, collections, streams and file I/O make it robust.
Possible improvements: fines for overdue items, a database instead of CSV, a GUI.
